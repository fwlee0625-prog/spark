# 本地项目启动管理工具 · 产品需求文档(PRD)

版本:v0.1  
形态:Node 本地服务 + Web 管理页面

---

## 1. 背景与目标

### 1.1 背景

日常开发同时涉及多个本地项目(Node、Python、Vue 等)。每个项目都要在开发工具里单独打开终端、进入目录、输入命令启动,项目一多,操作繁琐,也容易忘记哪些项目在运行、占用了哪些端口。

### 1.2 目标

提供一个统一的本地管理面板,实现项目的**创建、启动、停止、重启和日志查看**,减少重复的终端操作。

### 1.3 非目标(v1 不做)

- 不做远程部署、不做线上服务管理
- 不做多用户、权限、账号体系
- 不替代 pm2 等生产环境进程管理工具
- 不做容器(Docker)编排

---

## 2. 目标用户与场景

**用户**:个人开发者,本机同时维护多个前后端项目。

**典型场景**

1. 早上开工:一键启动"前端 + 后端"分组,而不是开 3 个终端。
2. 调试时:在一个页面里切换查看各项目日志。
3. 端口冲突:启动失败时,明确知道是哪个项目占用了端口。
4. 收工:一键停止所有项目,且不残留 vite、webpack 等子进程。

---

## 3. 功能需求

### 3.1 优先级说明

- P0:v1 必须有
- P1:v1 尽量有
- P2:后续迭代

### 3.2 项目管理(P0)

| 功能       | 说明                               |
| -------- | -------------------------------- |
| 项目列表     | 展示名称、类型、状态(运行中/已停止/启动失败)、端口、启动时间 |
| 新建项目     | 选择目录,填写名称、启动命令、端口、环境变量           |
| 编辑/删除项目  | 修改配置;删除仅移除配置,不动项目文件              |
| 启动/停止/重启 | 单个项目的一键操作                        |

### 3.3 日志面板(P0)

- 每个项目独立日志,实时推送
- 支持清空、自动滚动开关
- 保留最近 N 行(默认 5000 行),避免内存膨胀
- 支持 ANSI 颜色渲染(P1)

### 3.4 智能识别与预填(P0 / P1)

新建项目选择目录后,自动识别并预填启动配置。

**Node / 前端项目(P0)**

- 根据锁文件识别包管理器:
  - `pnpm-lock.yaml` → pnpm
  - `yarn.lock` → yarn
  - `package-lock.json` → npm
- 读取 `package.json` 的 `scripts`,在页面列出可选脚本(优先推荐 `dev`、`serve`、`start`),用户点选即可生成命令,例如 `pnpm dev`。
- 根据依赖识别项目类型标签(Vue、React、Vite 等)(P1)。

**Python 项目(P0)**

- 检测 `.venv` / `venv` 目录、`requirements.txt`、`pyproject.toml`、`manage.py`、`app.py` / `main.py`。
- 预填启动命令,例如 `.venv/bin/python app.py`、`.venv/bin/python manage.py runserver`、`.venv/bin/uvicorn main:app --reload`。
- 自动附加 `PYTHONUNBUFFERED=1`,保证日志实时输出。

### 3.5 端口管理(P0)

- 启动前检测配置端口是否被占用
- 被占用时提示占用来源(已知项目名,或外部进程的 PID 与名称)
- 提供"仍然启动"和"取消"选项(P1)

### 3.6 分组启动(P1)

- 将多个项目归为一组(如"电商前端 + 后端")
- 支持整组启动、整组停止
- 组内可设置启动顺序和启动间隔(P2)

### 3.7 其他(P2)

- 启动崩溃自动重启(含次数上限)
- 开机自启、系统托盘(升级为 Tauri 壳时实现)
- 项目启动健康检查(端口可连通即视为就绪)

---

## 4. 交互设计要点

- **主页**:左侧项目列表(带状态色点),右侧日志面板;顶部有"新建项目"和"分组"入口。
- **新建流程**:选目录 → 自动识别 → 展示预填命令(可修改) → 保存。目标 30 秒内完成。
- **状态反馈**:启动中、运行中、已停止、启动失败 四种状态要一眼可辨;失败时在列表和日志中都能看到原因。
- **危险操作**:删除项目、停止全部需要二次确认。

---

## 5. 非功能需求

| 项   | 要求                                     |
| --- | -------------------------------------- |
| 性能  | 同时管理 20 个项目、10 个同时运行时页面不卡顿             |
| 可靠性 | 停止项目必须杀掉整个进程树,不残留子进程                   |
| 数据  | 配置保存为本地 JSON,可手动备份和迁移                  |
| 安全  | 服务仅监听 `127.0.0.1`,不对局域网开放              |
| 环境  | 启动项目时环境与用户终端一致(PATH、nvm、pyenv、conda 等) |
| 兼容  | v1 首要支持 macOS,其次 Linux;Windows 后续评估    |

## 7. 验收标准

1. 新建一个 pnpm + Vue 项目,选目录后能自动预填 `pnpm dev`,点击启动后页面能实时看到 vite 日志。
2. 新建一个带 `.venv` 的 Python 项目,能自动预填使用虚拟环境的启动命令,日志无明显延迟。
3. 点击停止后,`ps` 中不再有该项目的任何相关进程,端口被释放。
4. 配置端口已被占用时,启动前给出明确提示。
5. 关闭浏览器页面后,已启动的项目继续运行;重新打开页面后状态与日志可恢复显示。

## 8. 风险与待确认

- 登录 shell 启动方式(`zsh -ilc`)在不同机器上可能因 `.zshrc` 过重导致启动变慢,需要评估并提供可关闭选项。
- 部分项目会自行 fork 守护进程脱离进程组,此类项目的清理需要额外处理(如按端口兜底杀进程)。
- 是否需要支持 Windows,待确认。
