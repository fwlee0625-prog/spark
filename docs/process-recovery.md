# 退出与进程恢复

## 默认行为

关闭或重启 Spark 时，已启动的项目继续在后台运行。下次启动会读取数据目录里的 `runtime/`（开发是 `apps/server/data/runtime`，`pnpm start` 是 `~/.spark/runtime`），核对 PID、进程组和启动时间，恢复仍在运行的终端；已经退出的显示为停止。

恢复后可以继续看日志、停止和重启，不必把项目再拉起来一遍。多终端项目会按实际情况显示「部分运行」。

关闭浏览器页面**不会**停止项目。

## 改为随 Spark 一起停

设置里打开「退出 Spark 时停止所有项目」，保存后在**下一次退出**时生效。停止流程仍是：进程组 `SIGTERM` → 超时 `SIGKILL` → 必要时按端口校验 cwd 再兜底。

## Spark 离线期间

- 不会做崩溃自动重启
- 下次启动时不会自动拉起已经停掉的项目
- 项目输出写在 `runtime/`，页面仍按设置限制显示行数
- 重启 Spark 时，每条输出流最多回放最近 256 KiB，随后继续实时读取
- 日志文件在该终端重新启动时覆盖；持续运行及 Spark 离线期间会累积磁盘日志

## 注意

- 运行记录只适用于本机，不要当配置迁移
- 升级前已经启动的进程如果还在用旧的日志管道，需要用新版再启动一次项目，之后才能跨 Spark 重启恢复
- 编辑正在运行的项目配置前，需要先停止
