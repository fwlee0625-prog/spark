# 资源监控

Spark 统计自己管理的本机项目进程，帮助定位占用内存或 CPU 较多的项目。

## 页面入口

- 侧边栏「资源监控」：独立总览页，支持搜索、仅看运行中、资源排序，选择项目后查看趋势、终端及进程明细，也可直接切换日志。

- 首页：已管理项目的内存、CPU、进程数汇总；运行项目支持按资源占用排序。
- 项目列表：卡片展示当前资源占用，支持按内存或 CPU 排序。
- 项目详情：默认打开终端日志；切换到「资源监控」查看最近 15 分钟趋势、终端汇总和进程明细。
- 终端日志：工具栏展示当前终端的资源占用；资源明细中的「查看日志」可定位到对应终端。

## 统计口径

内存使用进程常驻内存 RSS，以字节采集并在页面换算单位。项目数据包含各终端及可追踪的子进程，同一个 PID 只计算一次。共享内存可能在不同进程的 RSS 中重复出现，因此汇总是参考值，不代表停止项目一定释放同等大小的内存。

CPU 使用相邻采样之间累计 CPU 时间的增量，除以采样间隔与逻辑 CPU 数量，显示占整机计算容量的百分比。首次采样需要建立基线，CPU 暂时显示采集中。

全局汇总仅涵盖已管理项目，不是整台机器的资源使用情况。浏览器页面、外部数据库和容器内部进程不会因为项目使用它们而自动纳入；脱离可追踪进程关系的后台进程也可能无法归属。

## 刷新和历史

后端默认每 3 秒统一采集一次，页面共享采样结果。查看多个页面不会各自启动一套采集任务。

趋势保留最近 15 分钟，存储在服务端有界内存中，Spark 重启后重新积累。项目重启、停止或采样缺失处不连续连线。启动中、已停止、采集不可用与数据过期分别显示，采集失败不会被当作零占用，也不影响项目启动、停止或日志。

## 接口

- `GET /api/resources`：当前资源快照，含全局、项目、终端及进程数据。
- `GET /api/projects/:id/resources/history`：指定项目的近期历史。
- `GET /api/events`：在已有状态事件之外推送 `type: "resources"` 的资源快照。

资源数据不写入项目配置或终端日志；现阶段不提供持久化历史、资源限额、告警或自动停止。
